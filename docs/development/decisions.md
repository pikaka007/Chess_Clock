# 设计决策记录（ADR 摘要）

只记录"会改变复现结果或行为"的决策，以及被否决的方案。每条给出证据来源。

## D1 计时核心与 Android 解耦（纯 Kotlin + 注入式单调时钟）

- **决策**：`core` 包不出现任何 `android.*`；所有状态转换接收 `nowElapsedMs: Long`。
- **理由**：验收里“3 秒后换手应得 57 000 / 58 000”“3+2 每次换手加 2 秒”“几十秒不刷新后一次补扣”
  这类判断需要毫秒级可控的时钟源；纯 JVM 测试即可，不需要 Robolectric 或设备。
- **实现**：`ClockState`（不可变状态机）+ `ClockController`（编排、持久化策略、对话框状态）。
- **证据**：`ClockStateTest`（14 项）与 `ClockControllerTest`（20 项）覆盖上述规则；
  JVM 测试合计 67 项（全部类与覆盖范围见 `docs/verification.md` §1）。

## D2 只有一个"结算"点

- **决策**：`ClockState.settle(now)` 是唯一扣时的地方，`tap/pause/tick` 都先调用它；
  超时判定在加秒之前。
- **理由**：需求要求"任何时刻最多一方扣时，任何有效换手只加一次步数和增量"。
  把扣时集中到一处，才能用少量测试覆盖全部组合（换手、暂停、超时、恢复）。
- **代价**：`settle` 每次都会把锚点前移到 now；内存里的 `remaining` 因此可能是"旧的"，
  但 `remainingAt(now)` 是按锚点实时算的，快照写入时也先结算，所以不一致不会外泄。

## D3 快照用自带的行式文本格式，而不是 JSON

- **决策**：`format=…\nversion=1\n…` 的自定义编码（`ClockSnapshotCodec`），逐字段校验。
- **理由**：`org.json` 在 JVM 单元测试里只是桩（未 mock 会抛异常），为了不引入 Robolectric
  就把编码写成纯字符串逻辑；同时它可直接 diff、可逐字段做范围校验。
- **拒绝方案**：Room / DataStore（为一个 400 字节的快照引入依赖与迁移成本）、
  Bundle-only（进程被回收就丢）。
- **损坏处理**：任何缺失/未知/越界字段 → 返回 null → 丢弃快照并回到默认设置页，
  同时给 `SNAPSHOT_DISCARDED` 提示。

## D4 跨重启策略：不猜，暂停 + 提示

- **决策**：快照记录 `bootId = "boot:<Settings.Global.BOOT_COUNT>"`。若与当前不一致：
  - 运行中的对局 → 转为 `PAUSED`，保留双方余时与锚点，提示"检测到设备重启…"；
  - 暂停/就绪/结束 → 原样恢复。
  - 同一 boot 内 → 运行中的对局按锚点补扣**一次**（可能因此判超时）。
- **理由**：`SystemClock.elapsedRealtime()` 的基准在重启后改变，两个不同 boot 的读数相减没有意义。
  宁可少算，不可多算；且必须告诉用户"关机期间的时间无法得知"。
- **兜底**：若 `BOOT_COUNT` 读不到（API 26+ 正常可读），返回每进程随机 id →
  跨进程恢复一律当"其他 boot"处理（保守暂停）。

## D5 重置/新对局确认框期间自动暂停

- **决策**：打开"重置"确认框时，若在计时则自动暂停；取消后恢复**原计时方**；
  确认则重置。新对局确认（从设置页或棋盘页触发）同理。
- **理由**：需求明确要求"避免用户在读弹窗时意外损失时间"。
- **被否决方案**：弹窗期间继续计时（会损失时间）、弹窗期间无条件暂停且取消后保持暂停
  （用户会莫名发现时钟停了）。

## D6 对话框提升到应用层

- **发现过程**：`ClockFlowTest.changingTheTimeControlMidGame…` 在模拟器上失败——
  从设置页发起"开始新对局"时，时钟被暂停但**没有任何弹窗**：因为弹窗写在 `BoardScreen` 里，
  而当时 `screen == SETTINGS`。
- **修复**：新增 `ui/ClockDialogs.kt`，由 `MainActivity` 在 `when(screen)` 之外渲染。
- **保留记录**：该缺陷的修复在提交 `638ca96` 中，测试用例保留为回归保护。

## D7 状态用"亮度 + 填充/描边 + 文字"三重表达

- **决策**：计时中的表盘使用浅色底 + 深色字（亮度反转）、3dp 描边、实心胶囊标签"计时中"；
  未计时/暂停为深底描边 + "未计时/已暂停"；超时为红描边 + "超时"。数字始终是最大元素。
- **理由**：需求 U9 禁止仅靠颜色；同时照顾色弱用户与强光环境。
- **无障碍**：整块表盘是一个合并语义节点，`contentDescription` 口语化播报
  "玩家二 表盘，剩余 3 分 0 秒，计时中"；`ClockFormat.spoken` 与视觉数字**同源截断**
  （修复了"屏幕 2:58、朗读 2 分 59 秒"的不一致）。

## D8 字号自适应 + 限制字体缩放上限

- **决策**：数字字号由 `BoxWithConstraints` 的可用宽/高推导（`min(H*0.34, W/6.4)`，24–132dp），
  数字行内部把 `fontScale` 上限压到 1.15。
- **理由**：时钟数字是固定宽度的"仪表"，不能因为系统字号 200% 就被裁掉；
  其余文字（玩家名、状态、按钮）完全跟随系统字号。
- **验证**：`font_scale=1.3` + `wm size 720x1280 / density 320` 下逐节点检查边界，无裁切。

## D9 加秒可视化

- **决策**：换手后 2.5 秒内，获得加秒的一方显示琥珀色"+2 秒"；棋盘控制条常驻"换手 +2 秒"。
- **理由**：3+2 对首次使用者是隐式规则；可视化让加秒可被看见、可被录像验证。
- **边界**：窗口由 `ClockUiState.incrementFlashMs` 决定，JVM 测试固定 2 500 ms 边界。

## D10 依赖与版本锁定在本地缓存

- **决策**：AGP 8.5.2 / Kotlin 1.9.24 / Compose BOM 2024.06.00 / Gradle 8.7，全部为
  `~/.gradle/caches` 中已存在的版本。
- **理由**：本机到 `dl.google.com` 的下载经常超时（lint 依赖首次就失败了 15 分钟后重试才成功），
  锁定缓存版本让"干净 clone + 离线构建"成为可能。
- **代价**：不是最新版本；对课程交付无影响。
